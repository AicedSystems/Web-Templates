# Stephanie Mendoza Website Launch Checklist

## 1. Collect from Stephanie

- Final approved text and images.
- Final Seller's Guide PDF.
- Follow Up Boss user API key, registered system name, and system key.
- Domain registrar login or access to the domain's DNS settings.
- Final editor username and a unique password stored in a password manager.

Never place credentials in Git, JavaScript, screenshots, or this document.

## 2. Create the Render web service

1. Push the reviewed launch commit to GitHub.
2. In Render, create a Blueprint from the repository's root `render.yaml`.
3. Choose a paid web-service instance for launch if consistent response time is important. Confirm pricing in Render before selecting it.
4. Enter every secret value requested by the Blueprint.
5. Wait for `/healthz` to report healthy.
6. Open the temporary `onrender.com` URL before connecting the domain.

Required production variables are documented in `.env.example`. `SECRET_KEY` is generated by the Blueprint.

## 3. Verify the temporary production URL

- `/`, `/buyers`, `/sellers`, `/agents`, `/reviews`, `/blog`, and `/contact` return successfully.
- `/admin/blog` requests editor credentials and rejects incorrect credentials.
- Content Studio image/video upload, replacement, and removal work.
- Buyer, Seller, Agent, and Contact forms create the expected Follow Up Boss records.
- Calendly opens from every scheduling CTA.
- Buyer PDF opens and downloads; add and verify the Seller PDF when received.
- Supabase-managed images and videos load without exposing the secret key.
- Browser console and Render logs have no unexpected errors.

Use clearly labeled test contacts and remove them from Follow Up Boss afterward if Stephanie does not want to keep them.

## 4. Connect the domain

1. Add the chosen root or `www` domain under the Render service's **Settings → Custom Domains**.
2. Copy the exact DNS records Render provides into the registrar.
3. Remove conflicting records only after confirming their purpose. Render advises removing conflicting `AAAA` records because its web services currently use IPv4.
4. Verify the domain in Render and wait for its managed TLS certificate.
5. Confirm HTTP redirects to HTTPS and select one canonical hostname (`www` or root).
6. Keep the `onrender.com` address enabled until the custom domain passes the final smoke test.

## 5. Final live smoke test

Check at 375px, 768px, 1024px, and 1440px:

- Navigation, mobile menu, keyboard focus, and every CTA.
- No horizontal overflow, overlap, missing image, or unexpected animation.
- Buyer, Seller, Agent, and Contact forms.
- Calendly modal, Escape close, and focus restoration.
- Reviews and resource carousels.
- Blog list, article pages, thumbnails, and related articles.
- PDF view/download links.
- Footer phone, email, Facebook, and Instagram links.
- Reduced-motion behavior.
- Content Studio authentication and one harmless draft/save cycle.

## 6. Handoff and rollback

- Store the editor login and hosting credentials in a password manager.
- Do not share the Supabase secret key, Follow Up Boss keys, database URL, or `SECRET_KEY` with the client.
- Record the launch commit hash and successful Render deployment ID.
- If a launch regression appears, roll Render back to the last known-good deployment before editing production data.
